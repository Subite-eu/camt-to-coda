# External CODA example research and compatibility corpus

All 29 fixtures are available in the browser’s **Example files** view (`/#examples`): filter **Provenance → Third-party fixture** and **Format → CODA**. Each file states its publisher, unverified bank authorship, Belgian format scope, acceptance/rejection status and usage terms. **Save original file** retrieves unchanged pinned bytes; the publisher link remains available if browser access is blocked. See the [download guide](../../docs/user-guide.md#find-and-download-example-files).

Verified **2026-10-11**. This collection contains **29 unique, unchanged third-party CODA fixtures**, deduplicated from **65 downloaded files** and their parser-port mirrors. **No complete bank-published CODA original was verified.** A Belgian bank identifier or BIC inside a developer fixture does not establish bank authorship or production-export provenance.

The [manifest](manifest.json) records immutable source URLs, exact source/container SHA-256 and byte sizes, archive members, encoding, classification, licensing evidence, equivalent mirrors and independently extracted literal facts. The [research inventory](research.json) records official Belgian bank services, specifications, unavailable examples and false positives. The separate [worldwide bank catalog](../bank-catalog/README.md) records bank-published CAMT material and bank reporting availability.

## What is covered

| Classification | Unique fixtures | Interpretation |
| --- | ---: | --- |
| Complete developer fixture | 23 | Complete record envelope; semantic validity is tested separately |
| Intentionally invalid globalisation fixture | 2 | Includes one shortened record; retained as negative cases |
| Generated by a third-party CSV-to-CODA converter | 2 | Explicitly generated examples, not bank exports |
| Header only | 1 | Unsupported version and incomplete statement |
| Synthetic empty developer fixture | 1 | Missing closing-balance record |

Four fixtures reconstruct independently verified account, balance, booked-movement and monetary-detail facts: `acsone-02`, `wimverstuyf-05`, `wimverstuyf-06` and `tryton-01`. The first three support successful CAMT XML conversion. Every target from v02 through v13 is tested: `acsone-02` and `wimverstuyf-06` pass all 12 bundled schemas; `wimverstuyf-05` passes v02 and v07–v13, and explicitly rejects v03–v06 because its aggregate summary has no independent transaction-detail amount. Those versions require an amount on every detail. **Tryton is a model-extraction positive with a source defect:** its original record2.2 at line93, positions99–109 contains the counterparty BIC placeholder `000000000`, which cannot be emitted as a valid ISO20022 BIC. It also contains monetary details whose directions differ from the aggregate entry; CAMT v02 cannot represent those independent directions. Tryton XML output is explicitly rejected for every target version: v03–v06 first encounters the missing amount on an aggregate summary detail, while the other targets reject the invalid BIC. Tests retain these limitations rather than repairing the source.

The other 25 fixtures demonstrate recorded source defects, including edited opening/closing account mismatches, incorrect continuation/file flags, invalid OGM checksums, invalid field values, orphan monetary details and malformed/incomplete records. Their rejection is verified against an independent witness in the original text, rather than treating any converter error as sufficient evidence.

The corpus includes Belgian BBAN, Belgian IBAN and foreign IBAN layouts, multi-file envelopes, globalised amounts and detailed movements, information/continuation records, free communications, UTF-8 and Windows-1252 text. CODA records contain **128 characters**, not necessarily 128 UTF-8 bytes. The file containing non-ASCII UTF-8 characters must not be declared malformed merely because its encoded byte width is larger.

## Retrieve and test

Original source bytes are downloaded to the ignored `private-examples/coda-published/` cache; they are not redistributed in this MIT repository or included in browser sample downloads.

```bash
node scripts/fetch-coda-corpus.mjs
CODA_CORPUS_REQUIRED=1 npx vitest run --project node test/integration/coda-published.test.ts
```

Set `CODA_CORPUS_DIR` for another cache directory on both commands. Existing cache entries are verified before use. Fresh downloads require HTTPS, pinned source and container sizes/hashes, bounded downloads and decompression, and exact reviewed TAR members for the Tryton package. Source text, line endings and encodings are never rewritten.

Ordinary offline tests verify the public metadata. With `CODA_CORPUS_REQUIRED=1`, every original is required: a missing or changed file fails the test. The dedicated CI acquisition/test job must use this mode. `xmllint` is required for the three positive fixtures' output schema checks.

For the two simple fixtures targeting v03–v06, a sole information detail inherits the aggregate amount required by those schemas. Tests assert that exact value without introducing another booked movement.

The literal account, balance and movement expectations were independently extracted using Python fixed-position slicing and decimal arithmetic, following Febelfin CODA v2.6 record1 pp15–16, record2.1 pp17–18, record8 p26 and record9 p28. Do not regenerate those expectations from this converter's output. Globalised monetary detail rows are retained separately from booked `detail_sequence=0000` totals, avoiding double-counting.

## Belgian bank and vendor search

Official material was checked for Belfius, KBC, BNP Paribas Fortis, ING, Crelan, Argenta, Beobank and Banque Van Breda. These confirm CODA services or implementation details, but no anonymously downloadable complete original CODA statement was verified. BNP Paribas Fortis publishes record snippets; snippets are not complete fixtures. Febelfin publishes the authoritative standard, while the EPBF document is an older mirrored specification.

The research inventory also records an Odoo sample link requiring Google sign-in; Codabox feeds requiring API credentials; screenshots or PDF documentation from other vendors; Billit/Yuki CSV templates that are not CODA; and ValidateFin's explicitly fictitious CC-BY-4.0 sample pages whose original downloads were not acquired. Public page text was not reconstructed and relabeled as an original file.

This is a reviewed acquisition snapshot, not a claim that Belgian banks never publish samples. Future additions must retain exact downloaded bytes and document their actual publisher, rights, bank-export evidence, independent field facts and validation status.
